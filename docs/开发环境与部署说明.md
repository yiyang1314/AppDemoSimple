关键运行时耦合：

- `Rxbit.Brigade.Controll` 的 `LaunchExternalModule` 使用**源码树相对路径**启动外部模块（见 [MainWindow.xaml.cs](../Rxbit.Brigade.Controll/MainWindow.xaml.cs)）：

- `Rxbit.BrigadeApp` 是否直接调用 `Brigade.VideoPlayer`：**没有**。主程序自身有 `VideoMakerView`，独立使用 FFmpeg；VideoPlayer 为独立可执行程序。

### 2.3 NuGet 还原

工程同时存在两种依赖管理方式：

1. **`packages.config`（经典工程）**
   - 主程序：[Rxbit.BrigadeApp\packages.config](../Rxbit.BrigadeApp/packages.config)，包含 `CommunityToolkit.Mvvm 8.2.0`、`Microsoft.Extensions.DependencyInjection 7.0.0`、`Microsoft.Xaml.Behaviors.Wpf 1.1.142`、`System.*` 等。
   - ECU：`BrigadeTool.EcuServices\packages.config`（`System.Buffers` 等）。
   - 还原后的包目录在 `Rxbit.BrigadeApp\packages\`（当前工作区已存在）。
   - 注意：`BrigadeTool.CanDevices` 的 `Newtonsoft.Json` HintPath 写的是 `..\packages\Newtonsoft.Json.13.0.4\...`，而根目录下**没有** `packages\`；正确包目录在 `Rxbit.BrigadeApp\packages\`。若从零还原后出现该引用找不到，需修正该 HintPath 或调整包目录（**待确认**是否统一为 `Rxbit.BrigadeApp\packages`）。
   - 仓库无 `nuget.config`，默认使用 nuget.org；是否有内部镜像源**待确认**。

2. **`PackageReference`（SDK 风格工程）**
   - `Rxbit.Brigade.Controll`、`Rxbit.Brigade.HalconVision`、`Rxbit.Brigade.ZcanPro` 均引用：
     - `LiveChartsCore.SkiaSharpView.WPF` `2.0.0-beta.200`
   - `Brigade.VideoPlayer` 无 NuGet 包引用，仅使用框架自带 WPF/WinForms。

还原命令示例（在仓库根目录执行）：

```powershell
# 经典工程（packages.config）
nuget restore Rxbit.BrigadeApp\Rxbit.BrigadeApp.sln

# SDK 风格工程
dotnet restore Rxbit.Brigade.Controll\Rxbit.Brigade.Controll.csproj
dotnet restore Rxbit.Brigade.ZcanPro\Rxbit.Brigade.ZcanPro.csproj
dotnet restore Rxbit.Brigade.HalconVision\Rxbit.Brigade.HalconVision.csproj
dotnet restore Brigade.VideoPlayer\Brigade.VideoPlayer.csproj
```

> `nuget.exe` 未随仓库提供；也可直接使用 Visual Studio 的「还原 NuGet 包」。

## 3. 开发与调试步骤

### 3.1 还原与编译

推荐先还原，再按目标工程单独构建，避免安装工程（`.vdproj`）因缺少扩展而中断整个解决方案构建。

```powershell
# 1) 还原
nuget restore Rxbit.BrigadeApp\Rxbit.BrigadeApp.sln

# 2) 主程序（Debug / x86）
msbuild Rxbit.BrigadeApp\Rxbit.BrigadeApp.csproj /p:Configuration=Debug /p:Platform=x86 /t:Rebuild /v:minimal

# 3) 独立 WPF 模块（SDK 风格）
dotnet build Rxbit.Brigade.Controll\Rxbit.Brigade.Controll.csproj -c Debug -p:Platform=x86
dotnet build Rxbit.Brigade.ZcanPro\Rxbit.Brigade.ZcanPro.csproj -c Debug -p:Platform=x86
dotnet build Rxbit.Brigade.HalconVision\Rxbit.Brigade.HalconVision.csproj -c Debug -p:Platform=x86

# 4) VideoPlayer（需 .NET 9 SDK）
dotnet build Brigade.VideoPlayer\Brigade.VideoPlayer.csproj -c Debug
```

统一构建入口为根目录 [publish_all.cmd](../publish_all.cmd) / [publish_all.ps1](../publish_all.ps1)（详见第 6 节），会按模块编译并输出到 `publish\<模块名>\`。

[build_admin.cmd](../build_admin.cmd) 仍保留，但只做一件事：以 `Release|x86` **Rebuild** `Rxbit.Brigade.Controll`；日常全量或分模块发布请使用 `publish_all`。

| `DllNotFoundException` / 「找不到 zlgcan.dll 或其依赖项」 | 输出目录缺少 `zlgcan\` 子目录；或缺少 ZLG 内核 DLL | 使用 `publish_all.ps1` 发布（会自动复制 `zlgcan\`）；手工部署时把 `BrigadeTool.CanDevices\zlgcan\` 整个目录复制到 exe 同级，确认 `kerneldlls\`、`devices_property\` 完整 |
| `BadImageFormatException`（0x8007000B） | 进程位数与原生 DLL 不符（CAN DLL 均为 x86；`binlog.dll` 为 x64） | 以 x86 构建/运行；确认没有把 x64 的 `binlog.dll` 放入 32 位输出（是否必需**待确认**） |
| PEAK/GCAN/创芯设备打不开 | 未安装厂商驱动，或 DLL 未复制到输出对应子目录 | 安装驱动；核对 `peakcan\`、`gcan\`、`gcanfd\`、`cxkjcan\` 目录 |
| Kvaser 通道初始化失败 | 未安装 Kvaser 驱动（无 `canlib32.dll`） | 安装 Kvaser 官方驱动；确认位数 |
| FFmpeg 状态显示「未找到」 | `ffmpeg.exe`/`ffprobe.exe` 不在 PATH、常见目录或程序目录 | 放入 `exe` 同级或 `ffmpeg\`/`Tools\`；或在界面手动指定；主程序会持久化 `FFmpegPath` |
| CHM 编译提示「未找到 hhc.exe」 | 未安装 HTML Help Workshop | 安装 Workshop；或将 `hhc.exe` 放入程序目录/`Tools\`；或设置 `HTML_HELP_WORKSHOP` |
| CHM 编译失败（退出码 ≥ 2） | HHP/HHC/HHK 编码、路径、主题文件缺失等 | 查看编译输出日志；确认编码为 GB2312(936)（见第 5 节） |
| `dotnet build` 报找不到 `Newtonsoft.Json` | `BrigadeTool.CanDevices` 的 HintPath 指向不存在的根 `packages\` | 改为 `..\Rxbit.BrigadeApp\packages\...` 或在根目录补齐包目录（**待确认**团队约定） |
| 解决方案打开后安装工程不可用 | 未安装 Visual Studio Installer Projects 扩展 | 安装扩展后重开 `.sln`，或只构建具体 `.csproj` |
| 重新生成时提示文件被占用 | 程序仍在运行，或 `publish\` 目录被占用 | 关闭所有实例；必要时清理 `bin`/`obj` 后重建 |
| 视频无画面/无法播放 | 缺少系统解码器（N 版 Windows） | 安装 Media Feature Pack；或改用外部播放器验证文件本身 |

### 4.3 目标机权限与驱动

- **不要**把需要写日志/配置的程序装到受保护目录（如 `Program Files`）后再以普通用户运行；主程序把 `Logs`、`Config` 放在 exe 同级（`RadarConstaint.AppWorkPath`/`ConfigPath`）。
- 录制目录 `C:\Data` 为硬编码；目标机需存在该目录或允许创建/写入。
- 全局配置写入 `%APPDATA%\Brigade\`，当前用户需有写权限。
- CAN 驱动安装、USB 设备访问通常需要管理员权限；驱动本身不在仓库内。
- 若使用 CHM 帮助，注意 Windows 可能对来自网络的 CHM 加锁（文件属性中的「解除锁定」可解决）。

### 4.4 位数与目录一致性（重点）

- 所有 CAN 原生 DLL 为 **x86**；主程序请使用 `Debug|x86` / `Release|x86` 输出。
- `Rxbit.BrigadeApp.csproj` 同时定义了 AnyCPU、x64、x86 三套配置；`.sln` 的 `Any CPU` 映射到 `AnyCPU`。若以 AnyCPU/x64 运行并加载 x86 CAN DLL，会直接失败。
- 单工程构建输出（如 `bin\x86\Debug`）中缺少 `zlgcan\`；统一脚本会补齐，手工拷贝 `bin` 目录部署时需自行复制，这是 ZLG 设备「一接就报找不到 DLL」的最常见原因。

## 5. 已知约束与排错 FAQ

### 5.1 CHM 相关约定（来自现有实现）

1. **输出文件名固定为 ASCII**：`brigade_help.chm`（代码硬编码），避免中文文件名在部分查看器/系统上的兼容问题。
2. **编码固定 GB2312（代码页 936）**：`project.hhp`、`contents.hhc`、`index.hhk` 均以 `Encoding.GetEncoding(936)` 写入；HTML 主题为 UTF-8。
3. **HHC 结构**：单个根 `<UL>` 下嵌套主题；`<param>` 使用非自闭合写法（`<param ...>`），不使用 `<param ... />`。
4. **HHK 为扁平列表**：不嵌套分组，兼容 CHM 查看器。
5. **HHP 显式声明** `Contents=contents.hhc`、`Index=index.hhk`、`DefaultTopic=html/index.html`，并设置 `LCID=0x0804`、全文检索开启。
6. **编译前删除旧 CHM**：`CompileAsync` 会先尝试删除已存在的 `brigade_help.chm`，避免文件占用。
7. **退出码约定**：`hhc.exe` 退出码 `0` 视为成功，`1` 视为「完成但有警告」，`>=2` 才抛错；编译超时 30 秒。
8. `hhc.exe` 搜索路径与环境变量见 2.4（源码中的环境变量名为 `HTML_HELP_WORKSHOP`）。

### 5.2 构建/产物约束

- **SDK 工程已按模块分目录**：三个 `FolderProfile.pubxml` 分别指向 `publish\Rxbit.Brigade.Controll\`、`publish\Rxbit.Brigade.HalconVision\`、`publish\Rxbit.Brigade.ZcanPro\`，统一脚本也会先清理各自目录。全量/分模块发布统一走 `publish_all.cmd`；`build_admin.cmd` 仅保留为 Controll 单模块快捷构建。
- **安装包取统一发布产物**：`-BuildInstaller` 以 `publish\Rxbit.BrigadeApp\` 的实际产物生成 MSI，配置随 `-Configuration`（默认 Release），主程序保持 x86；不再引用 `obj\x86\Debug\`。
- **文件占用**：重新构建前关闭所有已启动的 exe；`publish\<模块名>\` 中若残留 `crash.log`，说明程序曾在该目录运行。
- **NuGet 路径不一致**：`BrigadeTool.CanDevices` 的 `Newtonsoft.Json` 指向根 `packages\`（不存在）；其余工程指向 `Rxbit.BrigadeApp\packages\`。
- **SDK 未锁定**：无 `global.json`；VideoPlayer 依赖 net9.0，团队应统一 SDK 9.x 版本（**待确认**）。
- **README 存在过期信息**：`BrigadeInstall/`、SkiaSharp/SharpDX 依赖、Enterprise 版 MSBuild 路径等与当前仓库不一致；以本说明和实际 `.csproj` 为准。

### 5.3 FAQ

**Q1：为什么 ZLG 设备连不上，但 PEAK/GCAN 正常？**
A：检查 exe 同级是否存在 `zlgcan\zlgcan.dll` 与 `zlgcan\kerneldlls\`。单工程构建不会复制该目录，使用 `publish_all.ps1` 发布会自动补齐；手工拷贝 `bin` 输出时需自行复制。

**Q2：为什么在主程序里选 ZLG 就报 `BadImageFormatException`？**
A：主程序被以 x64/AnyCPU(64 位) 启动，而 `zlgcan.dll` 是 32 位。改用 x86 构建/运行。

**Q3：CHM 能生成但左侧目录空白/乱码？**
A：确认 `contents.hhc`、`index.hhk`、`project.hhp` 为 GB2312(936)，HHC 使用单个根 `<UL>` 和嵌套结构，HHK 使用扁平列表。

**Q4：CHM 编译报「文件被占用」？**
A：关闭已打开的 CHM 查看器；代码会先尝试删除旧 `brigade_help.chm`，删除失败会继续，最终可能因占用失败。

**Q5：Controll 里点 HalconVision/ZCAN Pro 提示找不到可执行文件？**
A：这是源码树相对路径（`bin\Debug\net48`）。请先以 Debug 构建两个工程，或按 4.2-C 调整发布目录。

**Q6：VideoPlayer 发布后还要装 .NET 9 吗？**
A：统一脚本默认输出 `publish\Brigade.VideoPlayer\`（self-contained 单文件），目标机不需要 .NET 9；使用 `-VideoPlayerSelfContained:$false` 时才需要 .NET 9 Desktop Runtime。两种方式都仍需外部 FFmpeg 才有转码/合成能力。

**Q7：安装 MSI 后为什么没有 CAN 功能？**
A：当前 `-BuildInstaller` 生成的 MSI 已包含 `zlgcan\`、`cxkjcan\`、`gcan\`、`gcanfd\`、`peakcan\`、`RadarEcu\`、`sub-exe\`、`Tools\`、`ffmpeg\` 与 `Assets\favico.ico`（见 4.2-F）。若安装后仍无 CAN 功能，请先确认 `publish\BUILD-REPORT.txt` 中对应目录不是 `MISSING`，并检查目标机 CAN 驱动与 x86 运行环境。

**Q8：HalconVision 需要 HALCON License 吗？**
A：当前工程未引用 HALCON SDK，不需要。若后续接入真实 HALCON 算法，需要另行部署运行时与授权（**待确认**）。

## 6. 统一发布入口脚本

入口文件（仓库根目录）：

- `publish_all.cmd`：双击或命令行入口，内部以 `-NoProfile -ExecutionPolicy Bypass` 调用 PowerShell；无参数双击时默认 `Release` + 全部应用，结束后暂停。
- `publish_all.ps1`：主脚本，可直接带参数运行。
- `publish.config.json`：外部依赖额外候选路径（目录或完整文件路径，支持 `%ENV%`），路径不存在会自动忽略。

### 6.1 参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `-Configuration` | `Release` | `Debug` / `Release` |
| `-Module` | `All` | `All` 或模块名/别名，可逗号分隔多个；别名见下 |
| `-CollectExternalDependencies` | `$true` | 是否收集 Kvaser / FFmpeg / hhc；关闭用 `-CollectExternalDependencies:$false` |
| `-VideoPlayerSelfContained` | `$true` | `$true` 为 self-contained 单文件（win-x64）；`$false` 为框架依赖发布（目标机需 .NET 9 Desktop Runtime） |
| `-BuildInstaller` | 关闭 | 额外生成 `RadarApp` MSI；选择 `Installer`/`MSI` 模块时也会启用 |
| `-SkipRestore` | 关闭 | 跳过 NuGet 还原；默认在 `project.assets.json` 缺失时才还原 SDK 工程 |
| `-PublishRoot` | `publish` | 自定义发布根目录 |

模块名：`Rxbit.BrigadeApp`、`Rxbit.Brigade.Controll`、`Rxbit.Brigade.HalconVision`、`Rxbit.Brigade.ZcanPro`、`Rxbit.RdpAppUI`、`Brigade.VideoPlayer`、`Rxbit.Brigade.RadarApp`（MSI）。
常用别名：`App`/`Main`、`Controll`、`Halcon`、`Zcan`、`Rdp`、`Video`、`Installer`/`MSI`。

### 6.2 用法示例

```powershell
# 默认 Release 全量：清理旧产物 -> 还原/编译 -> 发布全部应用
.\publish_all.cmd

# Debug 全量（本机已验证）
.\publish_all.ps1 -Configuration Debug

# 只发布一个或几个模块
.\publish_all.ps1 -Configuration Debug -Module Controll,VideoPlayer

# VideoPlayer 改为框架依赖发布
.\publish_all.ps1 -Module Brigade.VideoPlayer -VideoPlayerSelfContained:$false

# 不收集外部依赖（只保留构建输出与 zlgcan）
.\publish_all.ps1 -CollectExternalDependencies:$false

# 额外生成 RadarApp MSI（需 Installer Projects 扩展）
.\publish_all.ps1 -Configuration Debug -BuildInstaller
```

### 6.3 执行流程与产物

1. 校验 MSBuild / Visual Studio / dotnet；清理 `publish\` 旧产物（保留 `_logs\`），被占用时明确报错并中止。
2. 按需还原：SDK 工程仅在缺少 `obj\project.assets.json` 时执行 `dotnet restore`；`packages.config` 工程检测到 `Rxbit.BrigadeApp\packages` 后跳过，避免无网络时长时间等待。
3. 通过 `.sln` 的 `Debug|x86` / `Release|x86` 映射按目标工程执行 `Rebuild`，保证主程序 x86、库工程 AnyCPU。
4. 将构建输出复制到 `publish\<模块名>\`（剔除 `Logs\`），并校验关键文件（含 `Assets\favico.ico`）。
5. VideoPlayer 使用 `dotnet publish` 直接输出到 `publish\Brigade.VideoPlayer\`。
6. 复制 `BrigadeTool.CanDevices\zlgcan\` 到主程序产物（构建不会自动包含）；按需探测并复制外部依赖。
7. 生成 `publish\BUILD-REPORT.txt`；任一编译/发布失败立即中止并提示日志位置。

完整日志在 `publish\_logs\publish_<Configuration>_<时间戳>.log`。

已实测：`-Configuration Debug` 全量发布通过；`publish\Rxbit.BrigadeApp\` 为 175 个文件、34.13 MB，含 `Assets`、`zlgcan`、`RadarEcu`、`sub-exe`、`Tools` 等目录；`publish\BUILD-REPORT.txt` 与 `_logs\` 日志正常生成。

### 6.4 外部依赖探测

总体顺序：`publish.config.json` 配置路径 → 专用安装目录/环境变量 → `Brigade.VideoPlayer` 自带目录 → 仓库 `tools\` → `PATH`。当前正式 FFmpeg 目录为 `D:\my-software\ffmpeg`（已写入 `publish.config.json`），探测优先命中该目录；不再使用 IDE 内置副本，仅当上述路径全部缺失时才回退 `PATH` 并将 IDE 副本标记为 `FOUND-IDE` 告警。

| 依赖 | 目标位置 | 内置候选（节选） | 缺失时 |
|---|---|---|---|
| ZLG `zlgcan\` | 主程序根目录 | 直接从 `BrigadeTool.CanDevices\zlgcan\` 复制（不做路径探测） | 告警并列入报告，不中止 |
| Kvaser `canlib32.dll` | 模块根目录 | `publish.config.json`、`%KVASER_HOME%`、`%ProgramFiles%\Kvaser`、`%ProgramFiles(x86)%\Kvaser`、`SysWOW64`、`PATH`；校验 PE 为 x86 | 警告并列入报告，不中止 |
| FFmpeg `ffmpeg.exe` / `ffprobe.exe` | 模块下 `ffmpeg\` | 正式来源：`publish.config.json` 的 `ffmpegSearchPaths` 已配置 `D:\my-software\ffmpeg`；其后依次为 `%FFMPEG_PATH%` / `C:\ffmpeg\bin` / `%ProgramFiles%\ffmpeg\bin` / `%LOCALAPPDATA%\ffmpeg\bin` → `Brigade.VideoPlayer\ffmpeg` / 仓库 `tools\ffmpeg` → `PATH`。不再使用 IDE 内置副本；仅全部缺失时回退 `PATH`，命中 IDE 副本则标记 `FOUND-IDE` 并告警 | 逐文件警告并列入报告，不中止 |
| HTML Help Workshop `hhc.exe` | 主程序 `Tools\` | `%HTML_HELP_WORKSHOP%`、`%ProgramFiles(x86)%\HTML Help Workshop`、`tools\hhc`、`PATH`；同时复制同目录 DLL | 警告并列入报告，不中止 |

`-CollectExternalDependencies:$false` 时全部标记为 `SKIPPED`，不复制任何外部文件。

`publish.config.json` 可用键为 `kvaserSearchPaths`、`ffmpegSearchPaths`、`hhcSearchPaths`，值为目录或完整文件路径数组，支持 `%ENV%` 展开。

### 6.5 打包约定与已知限制

- 图标为编译期嵌入 exe；脚本不把仓库根 `assets\` 整体复制进产物或安装包。主程序输出中的 `Assets\favico.ico` 必须保留，脚本会校验；MSI 仅额外带快捷方式图标 `LOGO.ico`（`assets\common\LOGO.ico`）与卸载快捷方式目标 `msiexec.exe`。
- `-BuildInstaller` 以 `publish\Rxbit.BrigadeApp\`（配置随 `-Configuration`，默认 Release）的实际产物生成 MSI：包含主程序、托管 DLL 与 `zlgcan`、`cxkjcan`、`gcan`、`gcanfd`、`peakcan`、`RadarEcu`、`sub-exe`、`Tools`、`ffmpeg`、`Assets`；缺失目录会在 `BUILD-REPORT.txt` 标记 `MISSING`。Installer Projects 扩展或 `devenv.com` 缺失时只提示并跳过 MSI，不中断应用发布。实测 Release：MSI 内 177 个文件（发布产物 175 个 + 快捷方式图标 `LOGO.ico` 与卸载目标 `msiexec.exe`）。
- 若 `publish\` 中的 exe 正在运行，清理会失败并中止；关闭程序后重跑即可，脚本可重复执行。
- 外部依赖与原生 DLL 的位数必须匹配 x86 主程序（Kvaser 已做 PE 校验）。
- FFmpeg 正式来源为 `D:\my-software\ffmpeg`（`publish.config.json` 的 `ffmpegSearchPaths`），发布时优先复制该目录的 `ffmpeg.exe`/`ffprobe.exe`，不再使用 IDE 内置副本；若报告出现 `FOUND-IDE`，说明配置路径不可用并已回退 `PATH`，需检查该目录是否存在。

11. `Rxbit.Brigade.html` 的 Python 脚本依赖清单（仓库无 `requirements.txt`）。
12. HALCON 后续接入计划（当前无 HALCON SDK 依赖，无需运行时与授权）。
13. MSI 默认安装到 `[ProgramFilesFolder]`，主程序在 exe 同级写 `Logs\`、`Config\` 的权限问题是否改为 `[LocalAppDataFolder]`（见 4.3）。
